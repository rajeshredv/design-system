Accessibility

  • A number on its own means nothing to a screen reader. Add hidden text with .badge__sr (for example "3 unread") and hide the bare number with aria-hidden, or put the context in visible text next to it. Don't rely on aria-label on a plain <span>, because many screen readers ignore it there.
  • The dot has no text, so give it role="img" and an aria-label, or hide it with aria-hidden="true" if the state is announced elsewhere.
  • If the count changes live, announce the change from a separate role="status" region. Don't make the badge itself a live region.
  • Contrast: the Rail badge uses BG/1 text on Draft-badge. That's about 3.8:1 in light mode (white on #F63B00) and about 4.8:1 in dark mode (#2B2B2B on #F06C66). The 9.6px text is small, so use the Rail badge only for short counts next to an icon.
  • Dark mode issue in Figma: the Default badge puts Text/Primary on Theme/yellow/1000. That's about 10:1 in light mode but only about 1.4:1 in dark mode (#E3E3E3 on #E4C100), so the number is hard to read. This is kept as designed and flagged for the design team. Until it's fixed, use the Muted badge on dark surfaces.

Accessibility

Chip

Accessibility

  • Filter chips are <button aria-pressed>, which screen readers announce as toggle buttons. Put a group of them inside an element with role="group" and an aria-label such as "Filters".
  • Menu chips use aria-haspopup and aria-expanded. The open look (Figma "Playing") comes straight from aria-expanded="true", so the visual state and the announced state always match.
  • Removable chips can't be a button, because the × is a button and buttons can't be nested. The root is a <span> and the × has its own name ("Remove Open now"). After a removal, move focus to the next chip.
  • The media chip's play and pause overlay is visual only. A single button can't also be a play control, so if playback needs a keyboard control, add a separate button in the menu the chip opens.
  • Focus shows a 2px --color-button-1000 outline. Figma has no focus state, so this was added in code.
  • Contrast: the Default label (Text/T3 on BG/2) is about 7.8:1 in light mode and 8:1 in dark mode. The disabled label (Text/T1) is below 4.5:1 by design, which WCAG allows for disabled controls.

Accessibility

  • The tooltip has role="tooltip", and the trigger points to it with aria-describedby, so screen readers read it after the trigger's name.
  • It appears on hover and keyboard focus (:hover and :focus-within on .tooltip-anchor). You can move the pointer onto it without it closing. Escape hides it (Vue component, or the small script on this page), which meets WCAG 1.4.13.
  • A tooltip is a hint, not a label. Icon-only buttons still need an aria-label. Never put links or buttons inside a tooltip.
  • Contrast: text is about 12.4:1 (#E3E3E3 on #222222) and List rows about 7.6:1. In dark mode the surface is only about 1.1:1 against the BG/1 page (#2B2B2B), so the tooltip's edge is hard to see. The text is still readable.

Accessibility

  • Use role="status" so the message is announced without interrupting. Use role="alert" (the urgent prop) only for errors.
  • Keep the live region in the page and change its content, rather than inserting a new region. Some screen readers ignore live regions that are added along with their text.
  • The count bubble is aria-hidden, so put the number in the message text too ("5 messages marked as read").
  • If it disappears on its own, give people time to reach the action (at least 5 to 10 seconds) and pause the timer while it's hovered or focused. Make sure the action can also be done some other way.
  • Contrast: white text on #273742 is about 12.3:1. In dark mode the surface is close to the page color, but the text stays readable.

Accessibility

  • Transient alerts are live regions: role="alert" for errors, which interrupts, and role="status" for success and limits, which is polite. The Modal banner is static content, so it has no live role.
  • Color isn't the only signal. Each tone has its own icon (thumbs-up, triangle, circle), and the message text must say what happened.
  • For the countdown, don't announce every tick. Keep .alert__timer outside any live region, or add aria-hidden and describe the wait in words.
  • Contrast: the Success icon (Button/800 on Button/100) is about 3.3:1 in light mode, just above the 3:1 minimum for graphics. The Limit hit icon (Alert-info/Color on Alert-info/100) is about 2.6:1 in light mode, below 3:1. The text alongside it carries the meaning. The Modal "Learn more" link (Button/800 on Alert-info/100) is about 3.5:1, below 4.5:1 for 14px text. All of these pass in dark mode.
