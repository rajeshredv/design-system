Components · Actions

Button

Buttons trigger an action, like Reply, Save, or Delete. Six variants set the emphasis, three sizes fit the layout, and every variant has the same five states. Use only one primary button per area.

Figma: Buttons-* (15 component sets) Node 2145:2682 and siblings 80 variants Heights 24 / 36 / 44px Light & dark

Class API

One stylesheet, button.css, styles every button. Combine a base class, one variant and one size. States come from native pseudo-classes and ARIA attributes, so there's nothing to toggle by hand except .btn--pressed for buttons that stay selected.

Playground

Hover, press, and tab to the live button to see the real interaction states. It follows the page theme.

Anatomy & sizing

  1. Container: auto-layout, horizontal, centered. Fixed height per size, so the label and loader states are the same height
  2. Padding (pink): horizontal --space-xl 12px (Large --space-3xl 20px)
  3. Label: BTN Small / BTN Medium / Large text style, never wraps
  4. Icon (optional): 20px, 8px gap (--space-l)
  5. Loader (Loading only): the Figma loader, colored with the label color so it switches with the theme

Component variables

Every button reads local variables. Override them on one element instead of editing the global tokens.

.my-context .btn {
  --btn-bg: var(--color-button-1000);  /* fill */
  --btn-fg: var(--color-bg-1);         /* label, icon and loader */
  --btn-ring: transparent;             /* 1px Activated stroke */
  /* size: --btn-height --btn-pad-x --btn-min-w --btn-radius
           --btn-font-size --btn-line-height --btn-letter-spacing
           --btn-loader-size --btn-icon-size */
}

Usage

HTML + CSS

<link rel="stylesheet" href="tokens.css">
<link rel="stylesheet" href="button.css">
<link rel="stylesheet" href="icon.css">   <!-- only for icons -->

<button class="btn btn--primary btn--medium" type="button">Reply</button>
<button class="btn btn--secondary btn--large btn--full" type="button">Cancel</button>
<a class="btn btn--link" href="/all">View all</a>

<!-- Activated (toggle) -->
<button class="btn btn--ghost btn--medium" type="button" aria-pressed="true">Edit</button>

<!-- Loading: wrap the label so it stays readable by screen readers -->
<button class="btn btn--negative btn--medium" type="button" aria-busy="true">
  <span class="btn__loader" aria-hidden="true"></span>
  <span class="btn__label">Delete</span>
</button>

<!-- Leading icon -->
<button class="btn btn--ghost btn--medium" type="button">
  <span class="btn__icon icon" style="--icon:url(assets/icons/forward.svg)" aria-hidden="true"></span>
  Forward
</button>

<!-- Disabled -->
<button class="btn btn--primary btn--medium" type="button" disabled>Reply</button>

Vue

Button.vue has no styles of its own. Load tokens.css and button.css once, globally.

<script setup>
import Button from "./design-system/components/Button.vue";
</script>

<template>
  <Button variant="primary" size="medium">Reply</Button>
  <Button variant="negative" loading>Delete</Button>
  <Button variant="secondary" size="large" full-width>Cancel</Button>
  <Button variant="ghost" :pressed="isActive">Edit</Button>
  <Button variant="link" href="/all">View all</Button>          <!-- small link -->
  <Button variant="link" size="medium">View all</Button>       <!-- medium link -->
  <Button variant="ghost">
    <template #icon>
      <span class="icon" style="--icon:url(assets/icons/forward.svg)"></span>
    </template>
    Forward
  </Button>
</template>

Light and dark mode

Nothing extra is needed. Buttons follow the OS setting. To force a theme, set data-theme on <html> or on any container:

<html data-theme="dark">          <!-- whole page -->
<section data-theme="light">       <!-- one area -->

In dark mode BG/1 is #2B2B2B, so Primary and Negative buttons get a dark label on a lighter fill. That's how Figma defines it, and it passes contrast better than the light theme does.

Accessibility

  • Use a native <button type="button"> for actions and <a href> for navigation. Both give you keyboard support and focus for free.
  • Focus shows a 2px --color-button-1000 outline with a 2px offset. Figma has no keyboard-focus state (its "Focus" frames are the Activated look), so this was added in code. Don't remove it.
  • Contrast, light: white on #0087ED is about 3.7:1, which only passes WCAG AA for large text. At 16px Medium it counts as normal text, so it falls short of 4.5:1. The hover color #0076CE passes at about 4.7:1. Negative is lower: white on #EB5757 is about 3.5:1 (hover 3.9:1), and Negative-secondary's #EB5757 on #FDEEEE is about 3.1:1. Ghost and Link labels (#0087ED on white) are about 3.7:1.
  • Contrast, dark: in dark mode Figma uses a dark label (#2B2B2B) on a lighter fill. That passes: about 5.8:1 on #4DADF5, 4.9:1 on hover #479EDF, and 5.7:1 on Negative #FF7D7D.
  • Secondary label is about 7.8:1 (light) and 8.0:1 (dark). The Secondary Disabled label is about 1.6:1 / 1.8:1, which is allowed for disabled controls but hard to read.
  • Loading: set aria-busy="true" and keep the label in a .btn__label. It's visually hidden, so screen readers still announce the action. Button.vue does this for you.
  • Activated as a toggle: use aria-pressed so assistive tech announces the on/off state. Button.vue only sets it when pressed is true, so ordinary buttons aren't announced as toggles.
  • Disabled buttons can't be focused. If users need to learn why an action is unavailable, use aria-disabled="true" with an explanation instead.
  • Icons are decorative (aria-hidden="true"); the visible label names the button. Icon-only buttons are documented on the Icon buttons page.
  • The loader spins slower when the user has prefers-reduced-motion set, and color transitions are turned off.

Figma inconsistencies

Kept as designed unless noted. Worth confirming with design.

  • Buttons-Primary-Large uses Text/Primary / Text/T3 instead of the blue scale. Code keeps Large blue, like Buttons-Primary-Fullwidth.
  • Buttons-Secondary/Small uses the Button/100 / Button/600 blue scale. Code keeps Secondary neutral.
  • Buttons-Secondary-Large 2145:2678 is 36px, identical to Buttons-Secondary/Medium; the real Large set is 3862:3194.
  • Secondary Activated uses a Text/T2 stroke at Medium but a Text/Primary stroke and label at Large.
  • Secondary Disabled has no layer opacity (it greys the label); every other variant uses 0.5 opacity.
  • Buttons-Primary-Fullwidth Activated label is Button/800; Primary Medium and Small use Button/1000.
  • Buttons-Primary-Negative-small is styled as Negative secondary, and its Loading and Disabled frames sit on BG/1 instead of the Negative tint. Its Hover/Activated labels use Negative/1000; Medium uses Negative/800. There is no filled Negative Small in Figma.
  • Buttons-Primary/Icon is a ghost button: its Focused state uses Button/1000 (Ghost uses Button/800) and its Loading frame has a BG/2 fill with no corner radius.
  • The small Link switches from BTN Small to BTN Medium on hover, so it grows from 56×20 to 65×24.
  • Ghost, Negative and Negative secondary have no Small/Large sets (Negative secondary has no Large). Code reuses the Medium colors.
  • Text styles use Zoho Puvi Semibold; code uses Medium by project decision.

Guidelines

✓ Do

  • Use one primary button per section, for the main action
  • Pair Primary with Secondary or Ghost for the other actions
  • Write labels as short verbs: “Reply”, “Save”, “Delete”
  • Use Negative only for destructive actions

✗ Don't

  • Stack several primary buttons next to each other
  • Wrap labels onto two lines. The label is nowrap
  • Use a Link button for an action that changes data
  • Use hex values directly. They won't switch with the theme
